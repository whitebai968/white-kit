# 在另一台 Mac 的 Codex 中安装独立 session 工作区 · v1.1.0

把下面整份提示词交给目标电脑上的 Codex。它可以配合本仓库源码使用，也可以单独作为重建规范。只复制一句“按之前方案安装”不能替代本提示词。

---

请在这台 Mac 上实现并安装“独立 session 工作区 v1.1.0”。这是一次本地安装请求：你可以在所需权限范围内检查环境、编写或使用下述源码、运行隔离测试、备份后合并文件管理规则、安装当前用户的后台服务。保留原有个人配置和文件，不上传或发送本机聊天记录。

如果当前目录中有本包的 `VERSION`、`src/`、`rules/` 和测试，优先使用提供的 1.1.0 源码，不从零改写；先读 README，检查 `python3 verify_package.py`，再按下述流程安装。如果我只给了这份提示词而没有源码，就按本提示词完整实现程序、规则、说明和测试，再部署；不要以“已创建几个文件夹”代替后台功能完成。

## 1. 必须达到的使用效果

我主要通过 Agent 工作。Codex 是主力，卡顿时会用其他工具接手。需要在我创建或继续使用的本地项目中，自动维护该 session 的完整原始历史副本和独立工作区。

```text
项目目录/
├─ 项目导航.md
├─ session A 的名字/
│  ├─ 会话说明.md
│  ├─ 历史记录.jsonl
│  ├─ 资料/
│  ├─ 工作/
│  │  ├─ 索引.md
│  │  └─ 日期-工作项/
│  │     ├─ 候选文件或程序目录
│  │     ├─ 验证/       按需创建
│  │     └─ 临时/       按需创建
│  └─ 成果/
├─ session B 的名字/
└─ 已归档/
   └─ 已归档 session 的名字.zip
```

项目与 session 是两层，不要改成“项目 → 共享任务 → 多个 session”，也不要继续用 `codex-file/日期-任务名` 作为新产物的默认落点。A 的历史和产物放 A 中，B 同理。

## 2. 目录的控制权

- `会话说明.md` 是 Agent 接手入口：目标、已确认决定、进度、主要文件相对链接和下一步。程序只初始化正文，并更新明确标记的同步信息区；保留 Agent 和用户编辑的其他内容，包括自动区之后的新增文字。
- `历史记录.jsonl` 是 Codex 已落盘会话文件的按字节副本，不是模型摘要。复制已有记录本身不调用模型、不需要 API key。
- `资料/` 由用户控制，Agent 默认只读，需要加工时把副本放自己的工作组。聊天窗口附件只按任务读取使用，不自动复制到资料目录；用户明确要求保存时才代为存入。处理后生成的文件放工作组。
- `工作/` 是 Agent 默认写入区，程序源码、报告、图片、候选成品都放在这里。按一批有明确目的的工作分组，同一工作项跨天继续复用，不每轮聊天都建一个新组。
- `工作/索引.md` 由 Agent 维护，列工作项、用途、当前推荐文件和状态。临时文件、验证、备份位于相应工作组内部；有实质差异需比较时才增加版本。“已采用/未采用”以用户决定为准。
- `成果/` 由用户手动选择保留。Agent 不因“做好了、验证通过或已部署”自动放入成果；只有用户明确授权具体文件和版本时才代为归档或更新。成果要带齐必要配图和附件，不能依赖待清理临时文件。
- 系统安装目录里的运行副本单独登记。日常生成内容仍在 session 的工作区；明确要求修改已有外部文件时按该次授权操作并登记位置。
- 用户新增文件保留原位，Agent 确认用途后登记；清理按工作组说明状态、引用和已有保留成果后，用户决定再执行。

## 3. 自动同步的行为

1. 使用真实 session ID 识别，显示名称只控制目录名。发现新会话，自动创建工作区。先接入当前安装会话，其余旧会话再次活动后接入，不一次性向所有历史项目铺开目录。
2. 从本机实际 Codex 状态识别 session 的名称、cwd、原始记录路径、归档状态。识别 `$CODEX_HOME`，未设置时才使用 `~/.codex`。读取数据库用只读方式；先核对实际 schema，不能凭猜测改写 Codex 数据。
3. 工作目录位于项目子目录时识别其项目根目录；在已标记的 session 工作区中操作时，仍使用该工作区所属项目。跳过内部子智能体和审核 session。
4. 独立后台进程每 2 秒检查更新，已有内容完整复制；复制到临时文件后原子替换。源文件复制期间变化则重试，不能发布复制一半的结果。源 JSONL 有未完成末行时忠实保留，读取方可忽略未完成末行或等更新。
5. session 改名时，整个工作区一起改名，资料、工作文件、成果和相对链接随之保留。同名、非法字符或超长名称做确定性处理，不能覆盖已有无关目录。
6. 归档时将完整工作区压缩为项目内 `已归档/<session名称>.zip`，包内顶层目录同名，并包含用于校验和恢复的元数据。先生成临时 ZIP，核对所有成员、逐文件 SHA-256 和源文件稳定性，再发布 ZIP 并清理已确认一致的原文件。取消归档时先在隔离目录校验解压，再恢复项目根目录中的工作区，成功后才移除 ZIP。归档后改名时同步更新 ZIP 名称及包内顶层目录。重名加 session ID 后缀，不覆盖无关 ZIP 或目录。使用持久事务日志，覆盖 ZIP 发布、源文件部分清理、解压目录发布、ZIP 清理等位置的异常退出恢复。归档未变化时不每轮解压重打包；源历史变化时更新包内副本。保留文件内容、空目录、符号链接本身、普通权限及修改时间；不跟随符号链接复制外部文件。FIFO 等特殊文件暂停归档；ACL、扩展属性、资源叉和硬链接关系不在本版保留范围，硬链接按独立文件存储。发现文件变化、磁盘不足、损坏 ZIP 或路径冲突，保留现有有效副本并记录可见错误，不能声称已完成。归档期间应停止其他进程向工作区写入。
7. 分叉创建自己的工作区，历史采用 Codex 的分叉记录；记录父会话 ID 便于追溯，不共享父会话产物、不自动复制资料与成果。
8. 源会话在数据库与活动/归档记录中均消失至少 15 秒，才同步删除对应原始副本。存在资料、产物、编辑过的会话说明或工作索引时，目录及这些内容保留并标明“源会话已删除”；只有完全未编辑且无产物的自动空模板可以一并清理。已归档的 session 删除后，同样只移除 ZIP 中的原始历史，已有用户内容仍以 ZIP 保留。不能把数据库读取失败、临时缺文件或归档移动判为删除。
9. 使用所有权标记、单进程锁、持久化状态和移动恢复记录；异常退出后重启能继续。源码格式不兼容、路径权限不足或遇到不安全的符号链接时，保留现状并明确记录错误。
10. 项目导航自动列会话入口，保留人工说明。已归档入口指向对应 ZIP；`--locate` 对已归档会话返回 `archive` 路径和空的 `directory`，Agent 应提示先在 Codex 取消归档，不能凭旧路径创建目录。它只是索引，不把各 session 的上下文混在一起。

## 4. 安装步骤

先执行只读环境检查：系统必须为 macOS；寻找可用的 Python 3.9+，使用它的真实绝对路径启动后台程序；确定实际 CODEX_HOME、当前 session ID 和当前项目。不要使用其他电脑的用户名、会话 ID、路径或状态文件。

有本包源码时：

1. 在包目录运行 `python3 verify_package.py` 和 `python3 run_tests.py`。测试必须用临时数据库和隔离目录，不归档或删除真实业务会话。如果校验不通过，先查明差异。
2. 阅读 `rules/AGENTS.fragment.md`，检查当前生效的全局 `AGENTS.md`、可能覆盖它的 `AGENTS.override.md` 以及项目级冲突规则。不要把整份现有 AGENTS.md 替换掉。
3. `python3 apply_rules.py` 默认仅显示差异。若已有同名“文件与产物管理”章节，检查后使用 `--replace-file-rules` 仅替换该章节；其他结构的冲突规则由你局部合并并保留无关指令。用 `--apply --backup-dir <本次工作组中的备份路径>` 应用。非默认 CODEX_HOME 显式传 `--codex-home <实际路径>`。这属于已授权安装的一部分，无须再让我重复确认一般规则选择。
4. 运行 `python3 src/install.py install --seed <这台电脑的当前session ID> --backup-dir <备份路径>`；非默认 profile 同样传 `--codex-home`。程序应先检查 profile 和当前 ID，发现不兼容时先适配和测试，不绕过检查。
5. 运行副本安装到当前用户的 `~/Library/Application Support/CodexSessionMirror/`，用 `~/Library/LaunchAgents/local.codex.session-mirror.plist` 登录后启动并在进程异常退出后重启。运行副本独立于 session 文件夹，session 改名不能让后台服务失效。不用模型自动化或聊天轮次承担文件同步。
6. 用安装后稳定路径的 `session_mirror.py --locate` 定位当前工作区，默认使用 `CODEX_THREAD_ID`，缺失时传真实 `--session-id`。将安装产生的说明、校验结果和备份登记到当前工作索引；不要自动放进成果区。

只有提示词时：实现等效程序和规则。推荐 Python 标准库完成文件复制、SQLite 只读检查、JSON、哈希校验、路径处理、进程锁和日志，macOS launchd 负责常驻。源码必须提供隔离测试、安装/状态/停止/启动与只读定位入口，做到相同的外部行为后再安装。不要把完整业务聊天记录硬编码进模板。

升级时保留原安装和规则备份，v1.0.0 已同步的归档文件夹会在升级扫描后转换为 ZIP。若要降级旧程序，必须先用新程序恢复所有 ZIP，并确认没有未完成归档事务，再停服务恢复旧代码；旧程序无法识别 ZIP 状态，不能直接覆盖回退。

## 5. 完成验收

- 隔离测试覆盖：新建、追加、同名冲突、整个文件夹改名、ZIP 归档/恢复、ZIP 及目录同名冲突、归档后改名、损坏 ZIP 和路径穿越拒绝、分叉独立、删除后用户内容保留（含说明末尾新增文字）、源暂时缺失、崩溃恢复、符号链接和定位；还要覆盖归档/恢复各提交阶段的中断恢复、源文件变动保留原件，以及真实后台子进程的 ZIP 往返。
- 真实当前会话：源记录与副本在同一稳定时点逐字节或 SHA-256 一致，目录位置正确；候选文件位于工作区，资料与成果不被自动填入。
- 可对当前安装会话做一次临时改名再恢复，验证工作文件的内容和相对位置不变。不要为了验证而删除真实业务 session；归档、删除用隔离数据测。
- launchd 服务确实处于 running，停止/启动和恢复同步可验证；重启机器尚未测试就明确说明，不把配置了登录启动当成已实测登录。
- 交付说明包含：实际目录、后台运行路径、如何定位/停用、测试结论、备份位置和未验证事项。发现权限或兼容问题时给出具体错误，不以创建了空目录宣布成功。

这是 macOS v1.1.0 的完整要求。它同步的是本机已有原始记录，不等于让第三方工具原生导入 Codex 会话，也不等于保存模型内部状态或引用的所有附件。
