# ZIP 归档与恢复

## 日常使用

在 Codex 归档 session A 后，程序将整个工作区打包为 `项目/已归档/A.zip`；ZIP 内是 `A/` 和程序使用的 `__codex_archive__.json` 校验清单。资料、工作文件、成果及内部相对路径都包含在内。取消归档后恢复项目下的 `A/`，成功才移除 ZIP。归档后改名会重打包为新名称；重名时追加 session ID，不覆盖用户文件。

自动压缩不等于用户选定成果；成果区内容保持用户控制。聊天上传附件没有自动入库功能，只有已落盘的文件随工作区归档。

## 完整性和恢复

先生成临时 ZIP，校验全部成员和逐文件 SHA-256，并确认源目录没有变化，再发布 ZIP。原目录逐项核验后清理，持久事务记录支持清理中断后继续。取消归档先验证 ZIP 身份、成员路径和哈希，再解压到隔离目录，验证恢复内容后发布目录，最后移除原 ZIP。

已归档内容无变化时不会每两秒重新压缩。源历史变化时更新包内副本；源 session 确认删除后只清除历史，用户内容继续留在 ZIP；未经编辑且没有产物的空模板可移除。

## 异常处理

- 归档前停止其他程序的文件写入；工具不对其他进程持有的文件描述符加锁。检测到打包或清理期间的变化时，原文件或剩余文件及已发布 ZIP 都保留，状态显示待重试。
- 磁盘空间应容纳原文件、临时文件和 ZIP。磁盘不足、特殊文件、损坏 ZIP 或恢复位置被占用时，错误写入同步日志/状态，不用空目录替代丢失的 ZIP。
- 进程中断通常在下次启动自动继续；若用户修改导致无法继续，先停服务，备份 ZIP、残留目录与 state。由 Agent 对比清单与残留文件，在独立位置恢复完整版本；不要直接删除残留文件或 archive_job。已清理的成员在 ZIP 中，变化的剩余成员需单独保留。
- 可手动解压 ZIP 到其他位置查看。自动管理的 ZIP 及内部校验清单应保持原样，继续编辑请先在 Codex 取消归档。

## 保存范围

普通文件字节、空目录、符号链接本身（不跟随读取外部目标）、POSIX 权限、纳秒修改时间可由本程序恢复。硬链接存成独立文件。macOS 扩展属性、Finder 标签、资源叉、ACL 不保留；FIFO、socket 和设备文件暂停归档。手动用其他解压器时，属性恢复效果取决于该工具。

## 升级和降级

v1.0.0 的已同步归档文件夹，在 v1.1.0 下一次扫描时压缩。应用规则和安装器均先备份。若要降级，先用新程序取消全部归档并确认事务完成，再停服务、恢复旧代码和规则；旧程序不认识 ZIP 状态，不能直接覆盖启动。
