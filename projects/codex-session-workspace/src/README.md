# 会话同步程序（session 工作区版本）

每个 Codex session 对应一个独立的本地工作区。程序以当前用户身份在 macOS 后台运行，不调用模型，原始记录按字节复制，不改 Codex 数据。

```text
项目目录/
├─ 项目导航.md
├─ session A 名称/
│  ├─ 会话说明.md
│  ├─ 历史记录.jsonl
│  ├─ 资料/                        用户控制
│  ├─ 工作/                        Agent 生成区域
│  │  ├─ 索引.md
│  │  └─ 日期-工作项/
│  │     ├─ 候选文件或程序目录
│  │     ├─ 验证/                  按需创建
│  │     └─ 临时/                  按需创建
│  └─ 成果/                        用户选择保留的版本
├─ session B 名称/
└─ 已归档/
   └─ 已归档 session 名称.zip
```

## 定位当前 session

Agent 每轮接手先定位自己的目录，读取 `会话说明.md` 和 `工作/索引.md`，需要追溯时再读 `历史记录.jsonl`。

```sh
python3 "$HOME/Library/Application Support/CodexSessionMirror/session_mirror.py" --locate
```

已归档时返回 `archive` ZIP 路径，`directory` 为 null；先在 Codex 取消归档恢复工作区，不按旧路径建空目录。

默认使用 `CODEX_THREAD_ID`，也可显式传 `--session-id 实际会话ID`。只读定位命令最多等 8 秒，不改变同步状态。标题改名后再次定位，使用返回的真实路径，不重建缓存中的旧目录。同名冲突时路径可能有 ID 后缀，所以不要根据标题猜路径。定位失败时检查后台服务并报告，不声称目录已同步。

本版已取消 `--bind-task`，也不读取旧的任务绑定配置。

## 同步与文件边界

- 每 2 秒扫描本机 Codex 数据库、会话名称和源文件变化。首次安装仅立即接入 `--seed` 指定的会话，其余历史会话再次活动后接入；新会话自动发现。内部子智能体、审核会话不生成独立用户工作区。
- 用 session 唯一 ID 识别工作区，目录名取 `name`，再回退到 session index 和 `title`；非法字符替换、过长名称截短，同名冲突加短 ID。数据库是内部格式，必要字段缺失时暂停并记录错误。
- 项目从会话 cwd 的最近项目标记确定；在已标记的 session 工作区内部运行时，复用该工作区记录的项目根目录。项目名并非会话名，两者不混用。
- 活跃会话改名移动整个文件夹；归档校验压缩为 `已归档/<session名称>.zip` 后清理原目录，取消归档校验解压恢复后移除 ZIP；归档后改名同步更新 ZIP 与包内顶层目录。相对路径保留。升级时已有归档文件夹自动转换；同名冲突加 ID 后缀，不覆盖无关文件。跨文件系统整体迁移不在本版范围。
- 分叉创建自己的目录，历史内容忠实取自 Codex 的分叉记录；不共享父会话的工作目录，不自动复制父会话的资料和成果。需要旧文件时，由用户指示或明确授权后复制所需副本到自己的工作区，并登记来源。
- `历史记录.jsonl` 是程序管理的原始副本。`会话说明.md` 的同步信息自动区由程序更新，其他正文由 Agent 维护；`工作/索引.md` 只初始化一次，后续由 Agent 维护。
- 聊天窗口附件不会自动复制到资料目录，用户明确要求保存时 Agent 才代为放入。程序仅创建空的资料/成果容器，不向其中生成文件；Agent 默认只读资料，只在工作区生成内容。用户明确要求放入或更新成果时，Agent 才执行该次授权。
- 源会话从数据库及活动/归档记录中消失至少 15 秒，才删除对应的原始副本。会话目录中有资料、产物或编辑过的说明/工作索引时，整个目录保留并标注源会话已删除。已归档时同样清理包内历史、保留其他内容为 ZIP。只有未编辑、无文件的自动空模板会一并移除。不会自动删除用户文件。
- 复制先写临时文件，再以原子替换发布；源文件复制期间变化就重试。源文件暂时含未完成的 JSONL 末行时，副本也忠实保留，读取者应忽略未完成末行或等下一次同步。
- 单写进程锁和移动日志支持重启恢复。说明、记录及状态不使用软链接；原始源文件、项目源码、附件和模型运行状态并非同一对象。

## ZIP 归档边界

归档前应停止其他程序向工作区写入。保留普通文件内容、空目录、符号链接本身、POSIX 权限和修改时间，不保留扩展属性、资源叉、ACL 或硬链接关系（硬链接复制为独立文件）；FIFO、socket 等特殊文件暂停归档。ZIP 另有 `__codex_archive__.json` 校验清单，勿手动改写；可以手动解压到其他位置查阅。

压缩和恢复需要容纳源文件、临时文件及 ZIP 的磁盘空间。进程中断通过 state 中的 archive_job 恢复；发现原件发生变化、ZIP 损坏或位置被占用时保留副本并报错。此时先停止服务、备份 ZIP、残留目录和状态，再由 Agent 核对恢复，勿直接删除事务记录。归档事务完成前不要启动旧版程序。降级至 v1.0.0 前先用新程序恢复所有 ZIP，确认无待恢复事务，再停服务恢复备份。

## 工作区管理

一批有明确目的的工作使用一个 `工作/日期-工作项/`，跨天继续复用。索引登记用途、当前推荐文件和状态；缓存和每个测试中间文件不逐项列入。版本只在有实质差异、需要比较时保留，临时文件、验证和备份归入所属工作组。

程序源码也是一种产物，例如本目录 `session-mirror/` 放在所属工作组里。安装到系统位置的运行副本是独立部署位置，不能因为已经运行就自动当作用户已归档的成果。工作区清理需用户授权；成果应该包含必要依赖，不能依赖将被清理的临时文件。

## 管理后台服务

```sh
python3 install.py install --seed 当前会话ID --backup-dir 备份目录
python3 install.py status
python3 install.py stop
python3 install.py start
```

运行副本位于 `~/Library/Application Support/CodexSessionMirror/`，状态及轮转日志在其 `state/` 内；LaunchAgent 位于 `~/Library/LaunchAgents/local.codex.session-mirror.plist`，登录时启动。部署程序独立于工作区，因此 session 文件夹改名不会让后台服务失效。

## 从旧版迁移

已有镜像从旧任务目录迁到 session 工作区，原 rollout 文件转换为同内容的 `历史记录.jsonl`。先验证新副本，再清理旧副本；旧任务目录里归属不明或共享的产物保留原位，不擅自分给某个 session。当前项目已明确归属的旧程序和过程文件由本次迁移整理到相应工作组。

项目导航只更新带自动标记的会话列表，保留人工说明。旧任务自动列表会被替换；旧的任务绑定文件不再使用，历史材料不按年龄或状态自动清理。

## 验证

```sh
python3 run_tests.py
```

请在发行包根目录运行上面的测试命令；已安装的运行目录不包含测试。测试使用隔离数据库和临时工作区，覆盖原始复制、目录改名/归档/恢复、分叉独立、旧版迁移、运行进程恢复、资料和成果保护、符号链接、同名冲突、定位和项目导航。
